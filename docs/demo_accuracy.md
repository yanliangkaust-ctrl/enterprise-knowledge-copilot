# Demo answer accuracy release gate

Golden fixture: `data/evaluation/demo_accuracy_golden.json`. It includes the actual four frontend presets and three variations each, with expected literal facts, unacceptable claims, ordered deployment facts, and exact source section/text/SHA-256 selectors. All eight bundled documents were reviewed; the expected answers use only relevant sections. No answers or preset question strings are looked up by backend/frontend generation.

Run `python scripts/validate_demo_accuracy.py after` from the repository root. This exercises the real FastAPI POST /query adapter, session recording, routing, retrieval, sufficiency, final claim verification and serialization through TestClient, with a fresh hash-indexed synthetic corpus and fresh sessions. It does not contact Render. The gate resolves gold selectors, requires every expected fact, rejects listed unacceptable claims, checks deployment ordering, validates citation/chunk/text/section integrity, and requires literal cited support for answer sentences. Tests additionally require every returned generated claim to be SUPPORTED. No general semantic entailment is claimed.

Before vs after: Deployment 1/4 -> 4/4; Architecture 0/4 -> 4/4; Security 1/4 -> 4/4; Incidents 0/4 -> 4/4. Reports with actual answers, cited evidence, routes, sufficiency and verification are in ignored `artifacts/demo_accuracy_before.json` and `artifacts/demo_accuracy_after.json`. The original report remains preserved. Permanent backend tests and CI execute the new accuracy gate. Golden data may only be changed after source review, not to accommodate failures.

The shared source-extractive selector recognizes procedures, request flow, explicit team assignments and causal sentences. Existing retrieval runs first; supported source chunks are preserved within the requested K, with new lexical candidates explicitly scored zero. Existing returned similarity scores are retained. Cause selection requires source cause language; impact-only text is not a cause. Answers cite only used chunks. Ownership and time grammar now distinguish responsibilities and conditional “what happens when” from a date request. Existing unsupported-fact/procedure protection remains active.

The frontend renders a safe, limited Markdown subset as escaped React elements (no HTML), and labels NOT_VERIFIED as claims not verified independently of the evidence grounding badge. Unknown or unsupported facts still rely on the existing refusal gates; lexical selection is not a general reasoning engine. Other corpus questions and ambiguous forms remain outside this sixteen-case acceptance guarantee. Deployment validation on the changed commit still needs GitHub CI/container and manual cloud smoke tests; no deployment has occurred.
